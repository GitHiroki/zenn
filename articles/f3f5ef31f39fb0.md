## はじめに

### gRPCとは

gRPCはGoogleが開発したオープンソースのRPC（Remote Procedure Call）フレームワークです。
HTTP/2を使った高速な通信と、Protocol Buffersによる型安全なインターフェース定義が特徴です。

### Protocol Buffersとは

Protocol Buffers（protobuf）はGoogleが開発したデータ形式です。
`.proto`ファイルでデータ構造とサービスを定義すると、各言語向けのコードを自動生成できます。
JSONと比べてデータサイズが小さく、パース速度も高速です。

### REST APIとの違い

| 比較軸 | REST | gRPC |
|--------|------|------|
| プロトコル | HTTP/1.1 | HTTP/2 |
| データ形式 | JSON（テキスト） | Protocol Buffers（バイナリ） |
| インターフェース定義 | OpenAPI等（任意） | `.proto`ファイル（必須） |
| コード生成 | 手動が多い | `protoc`で自動生成 |
| 通信方式 | リクエスト/レスポンス | ストリーミングも可能 |

### この記事でつくるもの

名前を送ると挨拶を返す、シンプルなgRPCサーバーをGoで実装します。

```
クライアント --「World」-> gRPC サーバー
クライアント <-「Hello, World!」-- gRPC サーバー
```

## 環境構築手順

### 1. 必要なツールのインストール

#### Goのインストール
```bash
brew install go
```

#### Protocol Buffersコンパイラのインストール
```bash
brew install protobuf
```

#### Go用protocプラグインのインストール
```bash
go install google.golang.org/protobuf/cmd/protoc-gen-go@latest
go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@latest
```

プラグインにパスを通す（`~/.zshrc`または`~/.bashrc`に追加）:
```bash
export PATH="$PATH:$(go env GOPATH)/bin"
```

### 2. プロジェクトの作成

#### ディレクトリ作成とモジュール初期化
```bash
mkdir hello-grpc && cd hello-grpc
go mod init hello-grpc
mkdir proto pb server
```

#### protoファイルの作成
`proto/hello.proto`を作成してサービスを定義する。

```protobuf
syntax = "proto3";

package hello;

option go_package = "./pb";

// リクエストメッセージ
message HelloRequest {
  string name = 1; // 挨拶する相手の名前
}

// レスポンスメッセージ
message HelloReply {
  string message = 1; // 挨拶メッセージ
}

// サービス定義
service Greeter {
  rpc SayHello (HelloRequest) returns (HelloReply);
}
```

**ポイント:**
| 項目 | 説明 |
|------|------|
| `syntax = "proto3"` | Protocol Buffers v3を使用（現在の標準） |
| `package hello` | protoのパッケージ名。`grpcurl`で呼び出す際に使う（`hello.Greeter/SayHello`） |
| `option go_package` | 生成されるGoコードのパッケージパス |
| `message` | リクエスト/レスポンスのデータ構造を定義 |
| `service` / `rpc` | 呼び出せるメソッドを定義 |

#### Goコードの生成
```bash
protoc --go_out=. --go_opt=paths=source_relative \
       --go-grpc_out=. --go-grpc_opt=paths=source_relative \
       proto/hello.proto
```

**コマンド解説:**
| オプション | 説明 |
|-----------|------|
| `--go_out=.` | メッセージ型のGoコードを出力（出力先: カレントディレクトリ） |
| `--go_opt=paths=source_relative` | .protoファイルからの相対パスに出力する |
| `--go-grpc_out=.` | gRPCサービスのGoコードを出力 |
| `--go-grpc_opt=paths=source_relative` | 同上 |
| `proto/hello.proto` | 入力ファイル |

**生成されるファイル:**
| ファイル | 生成元オプション | 内容 |
|---------|----------------|------|
| `hello.pb.go` | `--go_out` | メッセージ型（HelloRequest, HelloReply） |
| `hello_grpc.pb.go` | `--go-grpc_out` | サービスインターフェース（GreeterServer） |

生成されたファイルを`pb/`に移動:
```bash
mv proto/*.pb.go pb/
```

#### サーバーコードの作成

`server/main.go`を作成してサーバーを実装する。

```go
package main

import (
	"context"
	"fmt"
	"log"
	"net"

	"google.golang.org/grpc"
	pb "hello-grpc/pb"
)

// server は GreeterServer インターフェースを実装する構造体
type server struct {
	pb.UnimplementedGreeterServer
}

// SayHello は gRPC リクエストを処理するメソッド
func (s *server) SayHello(ctx context.Context, in *pb.HelloRequest) (*pb.HelloReply, error) {
	log.Printf("Received: %v", in.GetName())
	return &pb.HelloReply{Message: "Hello, " + in.GetName() + "!"}, nil
}

func main() {
	lis, err := net.Listen("tcp", ":50051")
	if err != nil {
		log.Fatalf("failed to listen: %v", err)
	}

	s := grpc.NewServer()
	pb.RegisterGreeterServer(s, &server{})

	fmt.Println("gRPCサーバー起動中: :50051")
	if err := s.Serve(lis); err != nil {
		log.Fatalf("failed to serve: %v", err)
	}
}
```

**ポイント:**
| 項目 | 説明 |
|------|------|
| `UnimplementedGreeterServer` | protocが生成したインターフェース。これを埋め込むことで未実装メソッドのコンパイルエラーを防ぐ |
| `SayHello` | `.proto`で定義した`rpc SayHello`の実装。`in.GetName()`でリクエストの`name`フィールドを取得 |
| `grpc.NewServer()` | gRPCサーバーのインスタンスを生成 |
| `pb.RegisterGreeterServer` | サーバーにサービス実装を登録 |
| `s.Serve(lis)` | 指定したポートでリクエストの待ち受けを開始 |

#### 依存関係のインストール
```bash
go mod tidy
```

**コマンドの意味:**
`go mod tidy`は、コード内の`import`文を解析して必要なモジュールを自動でダウンロードする。
不要なモジュールがあれば削除もしてくれる。

:::message
**JSエンジニア向け補足:** Goのモジュール管理に馴染みがない方向けに、npmとの対応表を示します。

| Go | npm | 説明 |
|----|-----|------|
| `go mod tidy` | `npm install` | 依存関係をインストール |
| `go.mod` | `package.json` | モジュール定義ファイル |
| `go.sum` | `package-lock.json` | バージョン固定用のロックファイル |

Goは`import`文から依存関係を自動検出するため、`package.json`のように手動で依存関係を書く必要がない。
:::

**インストールされる主要モジュール:**
| モジュール | 役割 |
|-----------|------|
| `google.golang.org/grpc` | gRPCのGoライブラリ。サーバー/クライアントの実装に使用 |
| `google.golang.org/protobuf` | Protocol BuffersのGoランタイム。メッセージのシリアライズ/デシリアライズに使用 |

### 3. サーバーのビルドと起動

#### 方法1: 直接実行（開発時）
```bash
go run ./server/
```

#### 方法2: ビルドしてから実行（本番向け）
```bash
go build -o grpc-server ./server/
./grpc-server
```

**コマンド解説:**
| コマンド | 説明 |
|---------|------|
| `go run ./server/` | コンパイルと実行を一度に行う（開発時に便利） |
| `go build -o grpc-server ./server/` | バイナリを生成（`-o`で出力ファイル名を指定） |
| `./grpc-server` | 生成したバイナリを実行 |

:::message
`go run`は毎回コンパイルするため起動が遅い。
本番環境では`go build`でバイナリを作成して配布する。
:::

#### ビルド成果物の実行

ビルドすると単一の実行ファイル（バイナリ）が生成される:
```bash
# カレントディレクトリに grpc-server が生成される
ls -la grpc-server
# -rwxr-xr-x  1 user  staff  14497234 Jan 28 14:42 grpc-server

# 実行（Go のインストール不要）
./grpc-server
```

:::message
生成されたバイナリはGoがインストールされていない環境でも動作する。
依存ライブラリも含めて1つのファイルにまとまるため、配布が簡単。
:::

:::details Goのクロスコンパイル（補足）

GoはGOOSとGOARCH環境変数を指定するだけで、異なるOS/アーキテクチャ向けにビルドできる。
Mac上でLinuxバイナリを作成できるなど、DockerやCI/CD環境でのビルドに便利。

```bash
# Linux (amd64) 向けにビルド
GOOS=linux GOARCH=amd64 go build -o grpc-server-linux ./server/

# Linux (ARM64) 向けにビルド（AWS Graviton, Raspberry Pi 等）
GOOS=linux GOARCH=arm64 go build -o grpc-server-linux-arm64 ./server/

# Windows 向けにビルド
GOOS=windows GOARCH=amd64 go build -o grpc-server.exe ./server/
```

**主なターゲット:**
| GOOS | GOARCH | 用途 |
|------|--------|------|
| `linux` | `amd64` | Linuxサーバー（一般的） |
| `linux` | `arm64` | AWS Graviton, Raspberry Pi 4 |
| `darwin` | `arm64` | macOS (Apple Silicon) |
| `darwin` | `amd64` | macOS (Intel) |
| `windows` | `amd64` | Windows |

:::

出力:
```
gRPCサーバー起動中: :50051
```

### 4. 動作確認

#### grpcurlのインストール（テスト用）
```bash
brew install grpcurl
```

#### リクエスト送信
```bash
grpcurl -plaintext -import-path ./proto -proto hello.proto \
        -d '{"name": "World"}' localhost:50051 hello.Greeter/SayHello
```

**コマンド解説:**
| オプション | 説明 |
|-----------|------|
| `-plaintext` | TLSなしの平文通信を使用（開発環境向け） |
| `-import-path ./proto` | `.proto`ファイルを探すディレクトリ |
| `-proto hello.proto` | 使用するサービス定義ファイル |
| `-d '{"name": "World"}'` | リクエストボディ（JSON形式） |
| `localhost:50051` | 接続先のホスト:ポート |
| `hello.Greeter/SayHello` | 呼び出すサービス/メソッド（`package.Service/Method`形式） |

> **Note:** `grpcurl`はgRPC版の`curl`。
> REST APIを`curl`でテストするように、gRPC APIをテストできる。

レスポンス:
```json
{
  "message": "Hello, World!"
}
```

## ディレクトリ構造とファイルの役割

```
.
├── go.mod              # Goモジュール定義
├── go.sum              # 依存関係のチェックサム
├── proto/
│   └── hello.proto     # サービス定義（Protocol Buffers）
├── pb/
│   ├── hello.pb.go     # 生成: メッセージ型の定義
│   └── hello_grpc.pb.go # 生成: gRPCサービスインターフェース
└── server/
    └── main.go         # サーバー実装
```

### ディレクトリ名の意味

| ディレクトリ | 名前の由来 | なぜこの名前を使うか |
|-------------|-----------|---------------------|
| `proto/` | Protocol Buffers | `.proto`ファイル（サービス定義）を格納。クライアントと共有するため分離 |
| `pb/` | **P**rotocol **B**uffers | 自動生成されたGoコードを格納。手書きコードと区別するため分離 |
| `server/` | Server | サーバーの実装コードを格納 |

> **Note:** `pb/`はGoのgRPCプロジェクトでよく使われる慣習的な命名。
> 他にも`generated/`（より明示的）や`gen/`などが使われることもある。

### 各ファイルの役割

| ファイル | 役割 |
|---------|------|
| `proto/hello.proto` | gRPCサービスとメッセージの定義。クライアント（Node.js等）と共有する |
| `pb/hello.pb.go` | `protoc`が生成。`HelloRequest`/`HelloReply`のGo構造体を定義 |
| `pb/hello_grpc.pb.go` | `protoc`が生成。`GreeterServer`インターフェースとクライアントコードを定義 |
| `server/main.go` | gRPCサーバーの実装。`SayHello`メソッドを実装し、50051ポートで待ち受け |

## gRPCの基本的な流れ

```
1. protoファイルでサービスを定義
        ↓
2. protocでコードを生成
        ↓
3. 生成されたインターフェースを実装
        ↓
4. サーバーを起動してリクエストを待ち受け
```

## まとめ

この記事ではGoでgRPCサーバーを実装する手順を一通り確認した。

- `.proto`ファイルにサービスとメッセージを定義する
- `protoc`でGoコードを自動生成し、生成されたインターフェースを実装する
- `grpcurl`を使えば`curl`と同じ感覚で動作確認できる

gRPCには今回触れていない機能もある。次のステップとして以下が挙げられる。

| 機能 | 概要 |
|------|------|
| サーバーサイドストリーミング | サーバーが複数のレスポンスを逐次返す |
| クライアントサイドストリーミング | クライアントが複数のリクエストを送る |
| 双方向ストリーミング | 双方向でリアルタイムに送受信する |
| インターセプター | 認証・ロギング等のミドルウェアを挟む |
| TLS | 本番環境での通信暗号化 |
